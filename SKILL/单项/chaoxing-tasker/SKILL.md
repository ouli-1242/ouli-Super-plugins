# Chaoxing Tasker（超星学习通任务助手）

通过浏览器自动化（browser_use 子代理 + 用户已登录的浏览器）完成超星学习通（chaoxing.com）的常规任务，并向用户汇报待完成任务清单与完成结果。

## 前置条件

- 浏览器必须已登录超星。验证方法：打开门户 URL 后页面能渲染课程/任务内容，而不是跳转到登录页。
- 门户入口：`https://i.chaoxing.com/base`（学生端首页）。
- 若未登录：立即停止操作，告知用户「请先在浏览器中登录超星学习通」，不尝试绕过多因素验证。

## 页面特征库（实战沉淀）

- **登录判定**：门户打开后跳转登录页或出现「登录」按钮 → 未登录，停止并提示。
- **课程卡片**：门户首页以课程名展示的卡片列表。
- **作业状态**：作业列表项状态字样「未交 / 已提交 / 已批改 / 错过提交」；截止时间显示「剩余 X 天 / X 小时」或具体日期。
- **任务点/课点状态**：章节页图标——未完成（灰色空心）→ 完成（绿色实心/对勾）；顶部概览常显示「已完成 X 个 / Y 个」或百分比。
- **签到入口**：进行中的签到有「签到」按钮；二维码签到需扫码、手势签到需绘图（两者不自动化）。
- **历史签到/活动判定**：状态列有「成功 / 已参加」才算完成；只有「已结束」而无状态标记者 → 标注「待确认」，不臆断为已完成。
- **讨论**：话题列表中已回复的话题会显示「已回复」标记（元素 span.topic_reply，文字「已回复」）；刚回复后标记未及时显示时，刷新页面再确认。无标记的话题需进入主题按自己的用户名/头像定位楼层核实。
- **分页/懒加载**：列表底部常有「加载更多」或页码，统计前先展开全部，避免遗漏。
- **收件箱（历史任务）**：门户的消息/收件箱入口（i.chaoxing.com/base）可查看历史任务记录（作业、签到、考试等通知），用于交叉核对任务状态。

## 任务类型与处理策略

### 1. 任务总览与汇报

- **快速总览（默认）**：门户 → 逐课程检查作业/考试/签到/章节进度统计/讨论话题数 → 输出一行一课的汇总表。章节只取进度统计，不深入每个任务点（省时）。
- **详细核查**：针对指定课程深挖——进入每个老师讨论主题核实自身回复、逐条核对签到历史、列出全部未完成任务点清单。
- **指定课程**：用户提供课程名或 URL 时，只核查该课程。
- **增量对比**：同一会话内第二次汇报与上次结果对比，对新增/完成的变化加标注。
- **历史任务核查**：课程内列表不完备或要确认历史任务时，到「收件箱」查看历史记录（作业/签到/考试等通知）交叉核对。
- 汇报格式（Markdown 表格）：

  | 课程 | 作业 | 考试 | 签到 | 课点/视频 | 讨论 | 建议操作 |
  |------|------|------|------|-----------|------|----------|
  |      |      |      |      |           |      |          |

- 状态标注：待完成 / 已完成 / 进行中 / 已过期 / 待确认。

### 2. 完成作业（Work）

1. 打开作业 → 提取全部题目与选项（题目可能分页，逐页提取至最后一题）。
2. 题型处理：
   - 单选 / 判断 / 填空：AI 直接作答（单选为 radio、多选为 checkbox）。
   - 多选：有不确定选项时标注并在汇报中说明，不盲目全选。
   - 简答 / 论述：尝试作答；依赖课堂内容无法确定的，报告并询问，不编造。
3. 逐题点击选项（按**选项文字**匹配，不要只按 ABCD 字母顺序点击）。
4. 填写完复核：检查未答题（页面答题进度条），补齐。
5. 提交前**必须征得用户确认**（除非指令中已明确「直接提交」）。区分「保存草稿」与「提交」。
6. 提交后截图结果页，报告得分（如有）与提交回执。

### 3. 完成在线考试（高风险）

- 默认策略：**只提取题目并给出答案清单**，由用户手动填写；或仅在用户明确授权后自动作答并提交。
- 注意考试时间窗口与剩余时间，操作不超时。
- 明确告知：考试提交后不可修改，自动作答有风险，需用户承担。

### 4. 签到

- **普通签到**：进入后点击签到按钮即可，报告签到成功。
- **限时 / 二维码 / 手势签到**：涉及反作弊，**不自动化**；仅打开签到入口，提示用户手动完成最后一步（扫码/绘图）。
- **历史签到复核**：按状态列「成功 / 已参加」判定；无状态标记者标「待确认」，不臆断已完成。
- 到期未开始：仅报告签到入口与时间。

### 5. 完成课点 / 视频（执行细节）

执行顺序：先做章节测验类任务点（快），再批量刷视频。

- **测验类任务点**：等同作业流程（提取题目 → 作答 → 提交/保存），完成后任务点变绿。
- **视频类任务点**：
  1. 打开视频任务点，播放器自动播放；把倍速调至 2x（播放器倍速按钮）。
  2. 防挂机：每隔几分钟检查播放进度（当前时间是否推进）；视频中途可能弹出小节题目 → 自动作答后继续。
  3. 防判定：长时间无交互时轻量滚动页面（有限度，避免触发异常检测）。
  4. 完成判定：视频进度 100% 且任务点图标变绿/对勾 → 自动进入下一个任务点。
  5. 每章结束后汇报：本章完成数 / 总数、剩余。
- **批量**：一次会话连续完成同一课程全部任务点；量大时按批次进行，每批汇报并询问是否继续。
- **最终验证**：回到章节页，确认任务点统计为「X / X」全部完成。

### 6. 完成讨论（论坛）

- **自身回复判定**：先看话题列表的「已回复」标记（span.topic_reply）——带标记的话题已回复，跳过；刚回复但标记未显示 → 刷新页面（F5）再确认；刷新后仍无标记则进入主题，按自己的用户名/头像定位楼层，已有自己楼层则跳过，没有则补回复。
- **生成内容**：围绕主题原创回复（中文 50~100 字），多个主题回复避免雷同，引用课程概念增强相关性。
- **回复**：进入主题 → 点击「回复」→ 输入内容 → 提交；完成后回到列表确认出现自己的回复。
- **新建主题**：按老师要求数量，标题应概括观点。
- 汇报：已回复主题数 / 需回复总数，标注缺口。

### 7. 任务执行调度

- 优先级：临期作业/考试 > 课点测验 > 课点视频 > 讨论 > 剩余时间充裕的大作业。
- 跨课程：先完成量小易处理的课程，再处理视频量大的课程。
- 长任务（上百任务点）：分批次推进，每批结束汇报进度并询问是否继续。

## 通用操作规则

- 页面元素以文字为准：点击任何按钮/选项前先读取文本，与目标匹配后再点击。
- **只读优先**：除明确指令要执行的写操作外，其余操作一律先只读查看再决定。
- 确认弹窗（「确认提交」「提交后不可修改」等）：先理解含义，需要确认的与用户核对后再点击。
- 翻页/滚动：列表或题目分页时先加载完整再统计，避免遗漏。
- 出错处理：某一步无法点击或不响应时，截图并报告当前 DOM 文本与页面状态，不强行操作。
- 未获取项如实标注「未获取到 / 待确认」，绝不编造状态。

## 安全与隐私

- 不处理验证码、不绕过反作弊、不模拟二维码/手势签到。
- 提交作业/考试前必须用户确认（除非明确授权）。
- 不读取、不记录、不保存任何用户凭证（cookie/密码）。
- 所有汇报基于页面可见信息，不臆造完成状态。

## 结束汇报模板

完成任务后输出：
- 本次完成：类型、任务名、结果（得分/成功回执）。
- 剩余待办：按课程分组的未完成任务清单（含截止时间与建议操作），若为批量任务附后续批次计划。
