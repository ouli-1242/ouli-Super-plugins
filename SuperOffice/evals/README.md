# evals/ — 基线证据

本包的纪律宣称能改变 agent 行为（数字真实、模板优先、证据交付、凭证安全）。本目录就是证据的存放地——没有它，"这些 skill 有效"就是一个未经验证的断言，恰好是纪律第一条禁止的事。

## 一条记录是什么

每个 skill（或每个场景）一个文件夹，以 skill 命名：

```
evals/
├── README.md            # 本文件
├── INDEX.md             # 每次 recorded run 一行（台账）
├── doc-draft/
│   └── 2026-09-21-template-first/
│       ├── scenario.md  # 交给 agent 的任务原文，逐字
│       ├── red.md       # 无 skill 基线：agent 做错了什么
│       └── green.md     # 载入 skill 后：什么变了
└── data-report/
    └── ...
```

- **scenario.md** — 交给 agent 的确切任务，附模型名称/档位与日期。不可复现的场景不叫证据。
- **red.md** — 无 skill 基线。写明失败在哪（编造数字、编造模板、没读回就声称做好了）。没有失败的 RED = 无物可教。
- **green.md** — 同一场景载入 skill 后的表现。写明是哪条约束产生了合规行为。

永远先 RED 后 GREEN。只有 green 的记录是证言，不是测试。

## 值得记录的东西（SuperOffice 特有）

- 用户**纠正了动词路由** → 在 `superoffice/` 记一条 + INDEX.md 加一行（`misroute`）。
- 模型**无视纪律编造了数字、引用或模板** → `pressure` 记录；这是本包的核心失效模式。
- 交付物**没读回就声称做好了** → 在 `verify-output/` 记一条。
- 凭证**在配置文件之外被处理** → 在 `office-mcp-setup/` 记一条（并按事故对待）。

## 诚实的边界声明

- 这些是**单模型、单操作者的观察**，不是基准测试。
- 转写文本从真实会话粘贴进来，密钥已脱敏（纪律第四条在这里同样适用）。
- 被证伪的记录追加更正说明，绝不静默删除。
